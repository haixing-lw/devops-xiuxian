# 金丹期（2~5年）· 自动化 · 云原生 · SRE

> 目标：从「人肉运维」到「自动化运维」，最终达到 **5 年运维经验（金丹大成）** 的出师标准。
> 出关标准：完成三层突破，你就是一位能独当一面、被团队信赖的高级运维 / SRE。

---

## 金丹一层 · 丹成二品（2~3年）

> 定位：高级运维。此层修炼「批量自动化 + 监控体系」的核心大法。

### 📜 功法（按顺序修炼）
1. Ansible：Inventory、Playbook、Role、变量、常用模块（file/command/service/copy/template）
2. Ansible 进阶：AWX（Web 管理）、批量变更规范、幂等性
3. 监控体系：Prometheus + Grafana 完整搭建，node_exporter、告警规则（Alertmanager）
4. 日志体系：Loki（或 ELK）集中收集，Grafana 统一看板
5. 脚本与 Ansible 结合：巡检、批量分发、定时自动化任务

### 💠 修为经验（必会知识点）
- Ansible 幂等性为什么重要；Playbook 与脚本的区别
- 监控四问：监控什么 / 阈值多少 / 告警给谁 / 如何响应
- 指标、日志、链路（Metrics / Logs / Traces）三支柱概念
- 告警要「少而准」：避免告警风暴，先做规则评审

### ⚔️ 实操历练（预计 120 小时）
- 用 Ansible 写一套「批量部署 Nginx + 初始化系统」Playbook，一次跑 10 台
- 搭建 Prometheus + Grafana，接入 10+ 台主机指标，做出业务大盘
- 用 Alertmanager 实现告警分级（critical / warning），对接钉钉/企业微信
- 部署 Loki 收集多台机器日志，在 Grafana 里按标签检索

### 🗡️ 武器
- [ansible](https://github.com/ansible/ansible)（自动化）｜[awx](https://github.com/ansible/awx)（Web 管理）｜[prometheus](https://github.com/prometheus/prometheus)（监控）｜[grafana](https://github.com/grafana/grafana)（可视化）｜[loki](https://github.com/grafana/loki)（日志）｜[devops-exercises](https://github.com/bregman-arie/devops-exercises)（内功自测）

### 🔥 突破条件
- [ ] Ansible Playbook 实现「从零初始化 10 台新机器」并交付文档
- [ ] 监控大盘覆盖业务核心指标，告警能分级触达
- [ ] 日志平台支撑「按错误关键字 1 分钟内定位到机器与时间点」

## 金丹二层 · 丹成一品（3~4年）

> 定位：高级运维。此层修炼「容器化 + CI/CD」的现代运维大法。

### 📜 功法（按顺序修炼）
1. Docker：镜像、容器、网络、卷、Dockerfile 编写、镜像仓库（Harbor）
2. Docker Compose：多服务编排、环境变量、日志与资源限制
3. CI/CD：Jenkins（或 GitLab CI / GitHub Actions）流水线：构建 → 测试 → 部署
4. 部署策略：蓝绿发布、滚动更新、灰度发布
5. GitOps 入门：Argo CD 概念、声明式部署思想

### 💠 修为经验（必会知识点）
- 镜像分层与缓存机制；为什么生产不用 `latest`
- 容器与虚拟机的本质区别；容器网络（bridge / host / overlay）
- CI 与 CD 的边界；流水线四个阶段：拉码 → 构建 → 测试 → 部署
- 回滚预案比发布本身更重要

### ⚔️ 实操历练（预计 120 小时）
- 把公司/自己的一个 Web 应用容器化（Dockerfile + Compose），一条命令启动
- 用 Jenkins（或 GitHub Actions）搭一条完整流水线：代码提交 → 构建镜像 → 推仓库 → 部署
- 实现一次蓝绿发布演练：旧版本、新版本流量切换与回滚
- 搭建 Harbor 私有镜像仓库，配置项目级权限

### 🗡️ 武器
- [docker_practice](https://github.com/yeasy/docker_practice)（Docker 心法）｜[jenkins](https://github.com/jenkinsci/jenkins)（CI）｜[act](https://github.com/nektos/act)（本地跑 Actions）｜[gitea](https://github.com/go-gitea/gitea)（自托管 Git）｜[argocd](https://github.com/argoproj/argo-cd)（GitOps）｜[harness](https://github.com/harness/harness)（平台）

### 🔥 突破条件
- [ ] 应用容器化交付，一条命令可启动、日志可查、配置可改
- [ ] 流水线从提交到部署全程自动化，构建失败能定位原因
- [ ] 完成一次发布/回滚演练并产出操作手册

## 金丹三层 · 金丹大成（4~5年）

> 定位：SRE / 架构师。此层修炼「云原生 + 稳定性治理」的顶层大法，突破即出师。

### 📜 功法（按顺序修炼）
1. Kubernetes：Pod / Deployment / Service / Ingress / ConfigMap / Secret、网络与存储
2. K8s 进阶：Helm 包管理、kubectl 效率、集群监控（Prometheus + K8s 指标）
3. 云平台：容器服务（ACK/EKS）、云上成本（FinOps）、多环境管理
4. 可观测性：Metrics + Logs + Traces 全链路，SkyWalking / SigNoz，告警智能降噪
5. SRE 思维：SLO / SLI / 错误预算、容量规划、应急预案、故障复盘（on-call 文化）
6. 稳定性治理：限流降级熔断、全链路压测、混沌工程思想

### 💠 修为经验（必会知识点）
- K8s 控制面与数据面；调度器、控制器的工作原理
- SLO 定多少合适（如 99.9% / 99.95%）；错误预算怎么花
- 故障复盘五问：发生了什么 / 影响多大 / 根因是什么 / 怎么避免 / 如何更快发现
- 「自动化一切」与「稳定压倒一切」的平衡

### ⚔️ 实操历练（预计 160 小时）
- 用 kubespray/kubeasz 部署一套生产级 K8s 集群（多节点 + 高可用）
- 把一个微服务应用完整落地到 K8s：Deployment + Service + Ingress + ConfigMap + HPA
- 用 Helm 封装应用发布模板，实现「改 values 即可部署到不同环境」
- 定义一套服务的 SLO，搭建大盘 + 告警 + 周报，模拟一次故障全流程复盘
- （进阶）用混沌工具做一次故障演练（节点宕机 / 网络抖动），验证自愈能力

### 🗡️ 武器
- [kubernetes](https://github.com/kubernetes/kubernetes)（正统心法）｜[kubespray](https://github.com/kubernetes-sigs/kubespray) / [kubeasz](https://github.com/easzlab/kubeasz)（集群部署）｜[k9s](https://github.com/derailed/k9s)（日常兵器）｜[lens](https://github.com/lensapp/lens)（K8s IDE）｜[helm](https://github.com/helm/helm)（包管理）｜[skywalking](https://github.com/apache/skywalking)（全链路）｜[sentry](https://github.com/getsentry/sentry)（错误追踪）｜[uptime-kuma](https://github.com/louislam/uptime-kuma)（可用性监控）

### 🔥 突破条件
- [ ] 独立部署并运营一套生产级 K8s 集群，能应对节点故障
- [ ] 微服务应用 K8s 全量落地，滚动更新与回滚顺畅
- [ ] SLO 体系落地：有指标、有告警、有周报、有一次完整故障复盘记录
