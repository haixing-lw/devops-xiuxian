# 筑基期（6个月~2年）· 系统运维小成

> 目标：从「管一台机器」到「管一批服务」，掌握系统运维的核心内功。
> 出关标准：完成三层突破考核，即具备中级运维实力，可向自动化与云原生进发。

---

## 筑基一层 · 固本培元（6~10个月）

> 定位：初级运维。此层修炼系统管理的「内功根基」。

### 📜 功法（按顺序修炼）
1. systemd：`systemctl` 管理服务、查看日志 `journalctl`、编写 service 单元
2. 日志体系：/var/log 结构、logrotate 日志轮转、日志采集初步
3. 磁盘与存储：分区、格式化、挂载、LVM 扩容、`du/df` 排查
4. 定时任务：crontab 语法、系统级 cron、at
5. 性能排查入门：`top` `vmstat` `iostat` `sar` 看懂 CPU/内存/IO
6. 监控入门：安装部署一个监控工具（Zabbix 或 Prometheus），配置告警

### 💠 修为经验（必会知识点）
- systemd 单元类型（service/socket/timer）；`daemon-reload` 什么时候用
- 磁盘满了怎么定位（大文件 / inode 耗尽 / 句柄未释放）
- crontab 环境变量坑；定时任务日志去哪看
- 性能排查套路：先看负载 → 再看 CPU/内存/IO → 定位到进程

### ⚔️ 实操历练（预计 60 小时）
- 把一台服务器上的 3 个服务做成 systemd 托管，开机自启 + 崩溃自动拉起
- 模拟一次磁盘写满，完成定位与清理全流程
- 配置 logrotate，让 Nginx 日志按天轮转、保留 7 天
- 部署 Zabbix（或 Prometheus + node_exporter），监控本机 CPU/内存/磁盘并配置告警

### 🗡️ 武器
- systemd / crontab（内功）｜[prometheus](https://github.com/prometheus/prometheus)（监控）｜[glances](https://github.com/nicolargo/glances)（系统监控）

### 🔥 突破条件
- [ ] 手写一个 service 单元文件并成功托管服务
- [ ] 独立完成「磁盘告警 → 定位 → 清理 → 恢复」全流程演练
- [ ] 监控系统能对 CPU 或磁盘阈值触发告警

## 筑基二层 · 五行相生（10~16个月）

> 定位：初级运维。此层修炼「服务部署与脚本自动化」的相生之道。

### 📜 功法（按顺序修炼）
1. Shell 脚本进阶：变量、条件、循环、函数、`set -e`、脚本排错
2. Web 服务：Nginx 部署、虚拟主机、反向代理、负载均衡（upstream）
3. 数据库：MySQL 安装、用户权限、常用 SQL、主从复制、慢查询
4. 缓存：Redis 安装、持久化、主从、常用命令、过期策略
5. 自动化思想：把重复劳动写成脚本；定时巡检脚本

### 💠 修为经验（必会知识点）
- Nginx 反向代理与负载均衡的配置差异；location 匹配优先级
- MySQL 权限模型；为什么备份要锁表/一致性快照
- Redis 持久化 RDB vs AOF 的选择
- 脚本三原则：有日志、有返回值、可重入（幂等）

### ⚔️ 实操历练（预计 80 小时）
- 用 Shell 写一个「服务器巡检脚本」：输出 CPU/内存/磁盘/关键进程状态，异常告警
- 部署一套 LNMP（Linux + Nginx + MySQL + PHP）并跑通一个站点
- 配置 Nginx 反向代理到后端两个 Tomcat，验证负载均衡
- 搭 MySQL 一主一从，主库写入、从库可读，模拟故障切换演练

### 🗡️ 武器
- [docker_practice](https://github.com/yeasy/docker_practice)（实战参考）｜Nginx / MySQL / Redis（三大法宝）｜[GoBooks](https://github.com/dariubs/GoBooks)（案头经书）

### 🔥 突破条件
- [ ] 巡检脚本在 10 台机器上跑通，输出统一格式报告
- [ ] 独立部署 LNMP 并上线一个应用，能回答「502 怎么排查」
- [ ] MySQL 主从复制演示成功，且能说出主从延迟的排查思路

## 筑基三层 · 法力初聚（16~24个月）

> 定位：中级运维。此层修炼「数据安全、系统加固、上云」三大法力。

### 📜 功法（按顺序修炼）
1. 备份与恢复：mysqldump / xtrabackup、文件级备份策略（全备+增量）
2. 安全加固：SSH 加固、最小权限、防火墙策略、Fail2ban、基础等保意识
3. 虚拟化：KVM / Proxmox 基本使用；容器概念铺垫（Docker 入门）
4. 云服务器：公有云（阿里云/腾讯云/华为云）ECS、安全组、快照、对象存储
5. 高可用思维：keepalived 虚拟 IP、主备切换原理

### 💠 修为经验（必会知识点）
- 备份三要素：备份什么、多久一次、怎么恢复（先练恢复！）
- 安全最小化原则：不开没必要的端口、不给多余权限、不用默认口令
- 快照与备份的区别；RPO / RTO 概念
- keepalived 脑裂问题及规避

### ⚔️ 实操历练（预计 80 小时）
- 设计并演练一次「MySQL 全库备份 + 误删恢复」完整流程
- 对一台生产样机做安全加固清单并逐项落地（附整改报告）
- 在公有云开一台 ECS，通过安全组只放行必要端口，配置云监控告警
- 用 keepalived 搭 Nginx 主备，杀掉主节点验证 VIP 漂移

### 🗡️ 武器
- [restic](https://github.com/restic/restic)（备份）｜[duplicati](https://github.com/duplicati/duplicati)（云端备份）｜[lynis](https://github.com/CISOfy/lynis)（安全审计）｜[algo](https://github.com/trailofbits/algo)（安全访问）

### 🔥 突破条件
- [ ] 完成一次真实的备份恢复演练并产出报告
- [ ] 安全加固清单 ≥15 项全部落地，能讲清每一项为什么
- [ ] 云上架构：ECS + 安全组 + 云监控 + 快照策略 完整交付
