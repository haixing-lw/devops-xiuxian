## 🔮 灵根检测（先答 5 题）

1. 深夜生产告警响起，你的第一反应是？
   - A. 先看监控大盘，判断影响面 → 阵修倾向
   - B. 查日志定位根因 → 符修倾向
   - C. 先隔离可疑流量，保护业务 → 剑修倾向
   - D. 拉流水线看发布记录 → 丹修倾向
   - E. 直接上机器看资源与配置 → 体修倾向

2. 你最享受解决哪类问题？
   - A. 指标异常 / 链路追踪 / 容量评估（SRE 味）
   - B. 数据一致性 / 备份恢复 / 慢查询（DBA 味）
   - C. 漏洞 / 入侵 / 加固（安全味）
   - D. 构建部署 / 自动化流水线（DevOps 味）
   - E. 系统调优 / 网络 / 基础设施（平台味）

3. 你更希望成为？
   - A. 保证「业务永不停」的守护者
   - B. 数据资产的第一责任人
   - C. 攻防两端的执剑者
   - D. 让发布如喝水般顺畅的炼丹师
   - E. 让一切跑得更快的奠基者

4. 你的「爽点」时刻？
   - A. 大盘上 SLO 恢复绿色
   - B. 数据从备份中完整找回
   - C. 入侵路径被成功阻断
   - D. 流水线一键全绿并上线
   - E. 万兆网卡跑满、延迟降低

5. 最想点亮的天赋？
   - A. 全链路可观测
   - B. 数据库性能调优
   - C. 安全应急响应
   - D. GitOps / 平台化
   - E. 内核与虚拟化

> **计分**：哪一选项最多，即为你主灵根（A→阵修 / B→符修 / C→剑修 / D→丹修 / E→体修）。并列时可双修。

## 🗡 阵修 · 可观测 / SRE（推荐指数 ⭐⭐⭐⭐⭐）

**心法**：把「看不见的故障」变成「看得见的指标」。
**境界路线**：金丹 SLO → 化神全链路 → 炼虚容量与混沌 → 合体稳定性体系。

### 功法
1. Prometheus 指标体系 + 告警分级
2. Grafana 大盘设计（业务视角优先）
3. Loki / ELK 日志平台
4. SkyWalking / SigNoz 全链路追踪
5. SLO / SLI / 错误预算
6. 容量规划与压测；混沌工程

### 核心武器
[prometheus](https://github.com/prometheus/prometheus) ｜ [grafana](https://github.com/grafana/grafana) ｜ [loki](https://github.com/grafana/loki) ｜ [skywalking](https://github.com/apache/skywalking) ｜ [uptime-kuma](https://github.com/louislam/uptime-kuma) ｜ [kubernetes](https://github.com/kubernetes/kubernetes)

### 历练
- 为业务定义 SLO 并上线大盘 + 告警 + 周报
- 完成一次全链路追踪排障（请求 → 网关 → 服务 → DB）
- 混沌演练：杀掉一个节点，验证自愈

### 突破标志
业务故障平均发现时间 < 5 分钟；SLO 达标率可量化汇报。

## ⚗️ 丹修 · 自动化 / DevOps（推荐指数 ⭐⭐⭐⭐⭐）

**心法**：把「人肉操作」炼成「一键执行」。
**境界路线**：金丹 Playbook → 化神流水线 → 炼虚平台工程 → 合体 GitOps 体系。

### 功法
1. Ansible 自动化（Inventory/Playbook/Role）
2. Docker 镜像工艺 + Compose 编排
3. CI/CD 流水线（Jenkins / GitHub Actions / GitLab CI）
4. Argo CD GitOps 声明式交付
5. 发布策略：蓝绿 / 滚动 / 灰度 / 金丝雀
6. 平台化：内部开发者平台（IDP）、自助化

### 核心武器
[ansible](https://github.com/ansible/ansible) ｜ [awx](https://github.com/ansible/awx) ｜ [jenkins](https://github.com/jenkinsci/jenkins) ｜ [act](https://github.com/nektos/act) ｜ [argocd](https://github.com/argoproj/argo-cd) ｜ [gitea](https://github.com/go-gitea/gitea) ｜ [dagger](https://github.com/dagger/dagger) ｜ [harness](https://github.com/harness/harness)

### 历练
- 一套 Playbook 批量初始化 100 台机器
- 流水线：提交 → 构建 → 测试 → 部署 → 通知 全自动
- 搭建 Argo CD，实现「Git 即部署」

### 突破标志
发布全自动且可回滚；新人 1 小时可自助上线一个服务。

## 🗡️ 剑修 · 安全运维（推荐指数 ⭐⭐⭐⭐）

**心法**：让攻击者「攻不进来、进来了也留不住」。
**境界路线**：金丹加固 → 化神检测响应 → 炼虚安全架构 → 合体零信任。

### 功法
1. 系统加固：SSH、权限、防火墙、Fail2ban
2. 漏洞管理：Trivy 扫描镜像与依赖
3. 密钥管理：SOPS / Vault
4. 安全审计：Lynis、等保合规
5. 应急响应：入侵排查、日志取证
6. 零信任与云安全

### 核心武器
[trivy](https://github.com/aquasecurity/trivy) ｜ [lynis](https://github.com/CISOfy/lynis) ｜ [sops](https://github.com/getsops/sops) ｜ [algo](https://github.com/trailofbits/algo) ｜ [GOAD](https://github.com/Orange-Cyberdefense/GOAD)

### 历练
- 输出一份 20 项以上安全加固清单并落地
- 模拟一次入侵检测演练：异常登录 → 定位 → 处置
- 用 Trivy 建立镜像/依赖漏洞扫描准入

### 突破标志
安全事件处置有 SOP；关键资产漏洞清零可汇报。

## 🧧 符修 · 数据库运维（推荐指数 ⭐⭐⭐⭐）

**心法**：数据是修真界最珍贵的资产，你负责让它「永不丢失、永远可用」。
**境界路线**：金丹主从 → 化神高可用 → 炼虚分布式 → 合体数据治理。

### 功法
1. MySQL 架构：主从、半同步、MGR
2. 备份容灾：全备 + 增量 + 定期恢复演练
3. 性能调优：慢查询、索引、参数优化
4. Redis：持久化、集群、缓存一致性
5. 云数据库：RDS / 云原生数据库
6. 数据治理：归档、脱敏、容量规划

### 核心武器
[restic](https://github.com/restic/restic) ｜ [velero](https://github.com/velero-io/velero)（K8s 数据）｜ [kopia](https://github.com/kopia/kopia) ｜ MySQL / Redis / 云数据库

### 历练
- 主从高可用 + 自动故障切换演练
- 「误删数据」恢复演练（备份还原全流程）
- 一次慢查询优化实战，写出优化报告

### 突破标志
RPO/RTO 指标明确且演练通过；核心库可用性 SLA 达标。

## 🛡️ 体修 · 系统/平台运维（推荐指数 ⭐⭐⭐⭐）

**心法**：身体（基础设施）是一切修行的根基，把它炼成铜皮铁骨。
**境界路线**：金丹系统调优 → 化神虚拟化/云平台 → 炼虚网络架构 → 合体基础设施平台。

### 功法
1. Linux 内核与调优：sysctl、IO 调度、性能分析
2. 虚拟化：KVM / Proxmox / 容器运行时
3. 云平台：ECS / VPC / 负载均衡 / 容器服务
4. 网络：VLAN / BGP / SDN 基础、流量治理
5. 存储：分布式存储（Ceph/MinIO）、备份体系
6. 高可用架构：多活、容灾、双中心

### 核心武器
[minio](https://github.com/minio/minio) ｜ [seaweedfs](https://github.com/seaweedfs/seaweedfs) ｜ [etcd](https://github.com/etcd-io/etcd) ｜ [kubesphere](https://github.com/kubesphere/kubesphere) ｜ [portainer](https://github.com/portainer/portainer) ｜ Linux / KVM / 云平台

### 历练
- 一次内核参数调优 + 压测前后对比报告
- 搭建分布式对象存储并接入业务
- 设计一套「同城双活」架构方案

### 突破标志
基础设施规模化（千台级）管理能力；架构方案可评审、可落地。

## 🔁 分支修行法则

1. **先通识，后专精**：三境九层必须扎实，金丹后方可选派系。
2. **一主一辅**：主修本派，辅修相邻派系（如阵修辅修丹修的自动化，事半功倍）。
3. **分支可换**：发现不合适，元婴期前换派系成本最低——基础能力通用。
4. **江湖通吃**：无论哪派，Linux、脚本、网络、监控四门内功人人必修。
5. 分支武器均可在 [awesome-devops](https://github.com/haixing-lw/awesome-devops) 中找到更多选择。
